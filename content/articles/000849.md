### De/re-explaining: reading aloud as a turning away from instrumental and toward cultural text and social context

Reading code aloud offers the opportunity to turn away for established approaches for instrumental explanations of code and instead towards interpreting code from a cultural and social point of departure. When proposing reading code aloud as a method for critical code studies, we are drawing inspiration from established methods from other research fields, in particular from arts-based methods, cultural studies and sound studies. Reading code aloud thus moves analyzing code and programming as a practice into an arena that is more akin to storytelling. It explicitly encourages researchers to reflect on how they ascribe meaning to and react to hearing and speaking code in a new format. Reflexive and autoethnographic element of the approach connects code as text to lived, embodied experience, as well as to each participants’ sensemaking processes around code. In our conversations and reading of code, this approach enables us to analyze how we each interpreted the meaning of the specific pieces of code that had been used in the project, but also on how hearing it being read aloud as such affected us. ### De/re-familiarizing: reading aloud as a development of common language about code

> *Some of them are known words, words I feel like I've never not known, words like collect, select, pivot, tally.*

The transmedial gesture of abandoning the screen and the visual experience for reading code aloud in an alternative resonant sensory register enables a powerful de-familiarization from the usual ways we encounter source code. This de-familiarization opens the opportunity to grasp code as an object from a distance, which in turn can enable developing a new, common analytical language to unpacking code as a cultural object. In particular, we found this de-familiarization is powerful for developing a new, shared language for code across disciplinary divides, as its focus on turning away from explanation of code did work towards undoing the epistemic authority derived from the act of programming itself. While not always possible or even preferable, we argue that methods which allow the authors of code to participate in the interpretive work of code are vital for richer, shared understanding of software, and can even help repair alienating and historically false dichotomies of “them” as the othered programmers and “us” as the users

### De/re-contextualizing: reading aloud for situated, affective analysis of code

Reading code aloud enables a de-contextualization from the screen and roles of “analyst” and “programmer”, which, in turn, opens new space for a re-contextualizing of code and its interpretations as coming from those who work with and on it. Drawing on research from feminist technoscience, we propose that reading code aloud allows for a more clearly situated approach to studying code and its significance. Donna Haraway

One way in which reading code aloud made clear the embodied and situated character of code was that it allowed for a space to engage with the affective or emotional character of code and programming. Evalyn et al. have written about the affective community that coded signs such as emojis can create in the digital humanities (*"But yeah, one word I remember. But this is experienced based, but I remember one word that was very hard to do was this word of collect. And I think I spent an entire day on it. (…) I remember, it was very disappointing to include this word collect, it was like a sort of a recognition of the materiality of this setup, and the infrastructure that we were working with, and that we were bound with, like a disappointing and like unnecessary word or name of an action."*

The object of this frustration was related to the cloud-based computational environment provided to us by Danish Royal Library, which necessitated running the Spark computational engine on one server and the R session on another for the code to successfully run. To solve this, we used the *collect* verb of the *dplyr* grammar, which is part of the influential *tidyverse* suite of data science tools for the R language (*collect* “forces computation of a database query”

The tactical moves related to “collect”, which frustratingly distracted from the data analytical task, are thus also important reminders of another aspect of the situated nature of code in the project, namely the material infrastructure in which its programming took place. The history of programming languages is characterized by an attempt to separate hardware from software and abstract away the machine

Reading code aloud emphasizes a reflexive and contextual approach to code and programming practices. The embodied and situated nature of interacting with code is often invisible in analyses of code. However, engaging with a method for an analysis of code that directs attention away from the screen and toward the lived and resonant experience of working with code offers the opportunity to shine light on the situated nature of the production and interpretation of code. Following scholars such as Haraway, all knowledge is situated and comes from somewhere, and accounting for this is a key aspect of understanding the power dynamics of knowledge production as such. With this, developing methods for engaging with the relationship between embodiment, code and programming is central for an understanding of the social and cultural construction, reception and understandings of code.

We found that moving into audio as the realm for analysis of code activated a number of de- and re-familiarizing movements. Firstly it de-explained the code as a useful, expertly knowable function from inputs to outputs and re-explained it as a living and interpretable text. Second, it de-familiarized code from being a language on screen which divided “programmer” and “analyst” into two separate roles, and re-familiarized code as something which we shared a common experience of and could create a common language about. Finally, it de-contextualized code from the idea of being disembodied, neutral and unsituated, and allowed re-contextualizing code as an embodied and affective practice, as well as created a space to appreciate how this practice involves and is shaped by infrastructure and relationships between hardware and software, as well as our relationships to those. Collectively such de- and re-familiarizing movements can allow a mode of critical engagement with and about code that takes its point of departure not just from a functional, but also a cultural, social and personal understanding and analysis of self-programmed as well as received code. With this, I argue that methodologies which work intentionally with processes of de- and re-familiarization provide a fruitful point of intervention for critical code studies work in the future. In proposing reading code aloud as one such method, I hope to hear from future scholarship that enables contextual, situated, reflexive and critical analysis of code and its text and context.
